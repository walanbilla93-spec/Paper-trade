[C-1] AUTH BYPASS WHEN AUTH_TOKEN IS NOT SET
  File : backend/middleware/auth.js : line 8
  Code : if (!token) return next();
  Issue: If the AUTH_TOKEN environment variable is missing or blank, ALL
         protected routes are completely open to unauthenticated requests.
         Every trade execution, settings change, and data endpoint becomes
         publicly accessible with no credentials required.

[C-2] CORS OPEN TO ANY ORIGIN
  File : backend/server.js : line 8
  Code : app.use(cors({ origin: '*' }));
  Issue: Any website can make cross-origin requests to this API on behalf
         of a logged-in user. Combined with C-1, any page a user visits
         could silently trigger trades or exfiltrate trade data.

[C-3] ORDER ENDPOINT ACCEPTS ZERO / MISSING PRICE FIELDS
  File : backend/routes/bybit.js : lines 117-130
         backend/lib/executor.js  : lines 21-36 (cleanSignal)
  Issue: cleanSignal() defaults entry, sl, and tp1 to 0 when not provided.
         A caller can POST an order with no price fields and execution
         proceeds through expensive Bybit API calls. A zero entry is then
         masked with "|| 1" in marketBrain.js:99, silently producing wrong
         position sizes instead of rejecting the order.

[C-4] NON-ATOMIC JSON WRITES — DATA CORRUPTION ON CRASH
  File : backend/lib/store.js : line 46
  Code : fs.writeFileSync(p, JSON.stringify(value, null, 2));
  Issue: If the process is killed mid-write (OOM, power loss, container
         restart) the JSON file is left half-written and unreadable. On
         next start, the store returns the fallback (empty object/array),
         effectively wiping trades, settings, or the journal silently.
  Fix  : Write to a .tmp file first, then fs.renameSync() atomically.

[H-5] RACE CONDITION IN RECONCILER — TRADE STATUS UPDATES DROPPED
  File : backend/lib/reconciler.js : lines 146-155
  Issue: A boolean `running` flag guards concurrent reconcile calls but is
         not atomic in Node's async model. Two async invocations can both
         pass the guard before either sets it. Both read trades from disk,
         make Bybit API calls, then both write back — whichever writes last
         silently discards the other's updates. OPEN/CLOSED status can be
         lost, causing positions to stay tracked as open after they close.

[H-6] UNHANDLED PROMISE REJECTION — TP/SL SILENTLY NOT SET
  File : backend/lib/executor.js : lines 217-221 (setTimeout block)
  Issue: The async callback that attaches TP/SL after order placement has
         no try/catch. If setTradingStopSafe() throws, the error is
         swallowed entirely. The trade is live with no stop-loss or
         take-profit attached, and the system falsely records it as pending.

[H-7] FLOAT PRECISION LOSS IN QUANTITY CALCULATION
  File : backend/lib/executor.js : lines 82-89
  Issue: positionUsdt / entry uses raw IEEE 754 division on exchange prices
         that can be very small for altcoins. The result is floorToStep()'d.
         For low-price tokens this can produce a qty that fails Bybit's
         minNotionalValue check (order rejected) or an oversized position
         that exceeds the intended margin.

[H-8] AI API KEYS STORED UNENCRYPTED IN SETTINGS JSON
  File : backend/routes/bot.js : lines 126-131
  Issue: Gemini, OpenRouter, Groq, and OpenAI keys submitted via the
         settings UI are written to data/bot-settings.json in plaintext.
         Any file backup, log tail, or directory listing exposes all keys.
  Fix  : Store API keys only in environment variables / secrets manager,
         never in the JSON config file.

[H-9] BYBIT HMAC SIGNS WITH EMPTY SECRET SILENTLY
  File : backend/lib/bybit.js : lines 19-23
  Issue: If BYBIT_API_SECRET is not set, getSecret() returns ''.
         crypto.createHmac('sha256', '') does not throw — it produces a
         valid HMAC with an empty key. This will be rejected by Bybit but
         only surfaces as a remote 401, not a clear local configuration
         error. The missing secret should be validated before signing.

[M-10] TRADE PURGE HAS NO ARCHIVE
  File : backend/routes/trades.js : lines 36 (delete existing[id])
  Issue: Trades closed more than 7 days ago are permanently deleted from
         the store with no backup copy. If a trade was incorrectly marked
         CLOSED (reconciler race, manual mistake), the record is gone
         forever — no audit trail, no dispute resolution with Bybit.

[M-11] CONFLICTING TERMINAL STATES NOT DETECTED
  File : backend/lib/stateMachine.js : lines 16-18 (getTerminalState)
                                       lines 22-23 (closeSignal)
  Issue: getTerminalState() returns the first terminal value found in
         [terminalState, status, state]. If a signal object has
         status='WIN' and terminalState='LOSS' (possible after a partial
         write or reconciler race), the function silently returns 'WIN'
         and ignores the conflict. PnL accounting will record a win for
         what was actually a loss.

[M-12] VOLUME DELTA RETURNS FAKE 50/50 ON EMPTY DATA
  File : backend/lib/sentinelBrain.js : lines 180-183
  Issue: When _priceMapSnapshot has no valid pairs (entries filtered to
         zero), the function returns { bull_pct: 50, bear_pct: 50,
         pair_count: 0 }. Consumers that don't check pair_count treat
         this as a real neutral signal and may allow or block trades based
         on data that does not exist.

[M-13] SCAN INTERVAL CAN OUTLAST ENTRY CONFIRMATION WINDOW
  File : backend/lib/v4Brain.js : line 24 (LOOP_MS = 20000)
                                   line 47 (ENTRY_CONFIRMATION_WINDOW_MS = 90s)
  Issue: If the event loop is busy and scan timing slips, a signal may
         never be evaluated before its 90-second confirmation window
         expires. The signal is silently invalidated with no log entry
         explaining why valid setups were missed.

[L-14] RSI CALCULATION — OFF-BY-ONE CANDLE GUARD
  File : backend/lib/sweepEngine.js : lines 36-37
  Issue: The guard requires candles.length >= len + 1 but the initial
         loop accesses candles[1] through candles[len], using exactly len
         deltas. The check should be length >= len. The extra candle
         required by the guard is never read, making the guard stricter
         than necessary and slightly skewing the RSI seed average.

[L-15] INCONSISTENT HTTP STATUS CODES ACROSS ROUTES
  File : Multiple routes (trades.js, journal.js, sentinel.js, etc.)
  Issue: Some routes return res.status(500).json(...) on errors; others
         return res.json({ ok: false, ... }) with HTTP 200. The frontend
         must defensively check the ok field on every 200 response to
         detect failures — a mismatch easy to miss during development.
